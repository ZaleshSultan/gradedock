# GradeDock — checklist выпуска в Google Play

Проверено по официальным источникам Google **7 октября 2026 года**. Приложение: **GradeDock**, пакет `com.zaleshsultan.gradedock`. Это инструкция для выпуска; она не означает, что приложение уже опубликовано или что Google одобрил релиз. Перед загрузкой сопоставьте декларации с окончательной Android-сборкой.

## 1. Действия владельца аккаунта

- [ ] Создать или использовать собственный Google Play Developer Account. Для нового аккаунта нужны возраст 18+, принятие соглашения и разовый регистрационный платёж **US$25**. Оплата, документы, принятие юридических условий и 2FA выполняются владельцем. [Регистрация Play Console](https://support.google.com/googleplay/android-developer/answer/6112435?hl=en)
- [ ] Пройти проверки личности и контактных данных, которые показывает Console. Юридическое имя, адрес, контакт и тип аккаунта должны соответствовать реальному владельцу. [Проверка личности](https://support.google.com/googleplay/android-developer/answer/10841920?hl=en)
- [ ] Для нового личного аккаунта подтвердить доступ к физическому Android-устройству через Play Console app: требуется Android 10+ и устройство без root. [Device verification](https://support.google.com/googleplay/android-developer/answer/14316361?hl=en)
- [ ] Для платной загрузки создать payments profile, внести свои банковские реквизиты и завершить требуемые проверки. Казахстан поддерживает регистрацию разработчика и merchant; валюта профиля по умолчанию — USD. [Поддерживаемые страны](https://support.google.com/googleplay/android-developer/answer/9306917?hl=en)
- [ ] До релиза подтвердить юридические сведения в privacy policy и действующий адрес для обращений. Email из публичного GitHub-профиля можно использовать только если владелец действительно готов принимать там обращения пользователей. Сам по себе публичный профиль не является подтверждением юридического имени.

## 2. Создать запись приложения

- [ ] Выбрать тип **App**, категорию **Education** и согласовать аудиторию с реальным позиционированием: планирование университетских оценок. Не отмечать детскую аудиторию ради охвата.
- [ ] Указать английский язык по умолчанию, добавить русский перевод из `store-listing.md`.
- [ ] Сразу выбрать **Paid**, если используете выбранную модель платной загрузки. Цена эксперимента: **990 ₸ для Казахстана / US$1.99 для США**; проверить, что Console разрешает эти локальные суммы, и скорректировать до ближайшей доступной цены.
- [ ] Подтвердить пакет `com.zaleshsultan.gradedock` до первого выпуска. Названия пакетов постоянны. Для новой записи использовать правильный release application ID и увеличивать `versionCode` при последующих загрузках. [Создание приложения](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en)

Приложение, которое уже было предложено бесплатно, нельзя затем сделать платным в той же записи. Платное приложение можно сделать бесплатным. Поэтому не публикуйте это приложение как Free для теста ценовой модели. [Настройка цен](https://support.google.com/googleplay/android-developer/answer/6334373?hl=en)

## 3. Проверить Android-сборку

- [ ] Использовать релизный **Android App Bundle (.aab)** для нового приложения в Google Play. APK нужен для установки и локальной проверки, но не заменяет AAB в этом выпуске. [Формат публикации](https://developer.android.com/studio/publish)
- [ ] Проверить **targetSdk 36 или выше**: с 31 августа 2026 новые обычные мобильные приложения и их обновления должны ориентироваться на Android 16 / API 36. [Требование API](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en)
- [ ] Подписать release AAB собственным upload key и включить **Play App Signing** при первой загрузке. Сохранить keystore и пароли отдельно от публичного репозитория. Не загружать debug-подпись как конечный релиз. [Подпись Android](https://developer.android.com/studio/publish/app-signing)
- [ ] Проверить окончательный manifest: нет рекламных SDK, логина, разрешений на контакты, геолокацию, SMS или внешнее хранилище. INTERNET permission в оболочке само по себе не доказывает передачу данных — проверить фактические запросы.
- [ ] Проверить установку на реальном Android: создать курс, изменить вес и баллы, оставить будущую работу пустой, поменять целевую оценку, закрыть и повторно открыть приложение.
- [ ] Проверить выключенный интернет; локальное сохранение после перезапуска; русскую и английскую версии; длинные названия; клавиатуру; Android Back; edge-to-edge/system bars; малый экран и увеличенный размер шрифта.
- [ ] Проверить экспорт JSON через системное меню Share и обратный импорт. Испытать повреждённый файл, слишком большой файл, отмену выбора и ошибку записи. Импорт не должен терять текущие курсы без понятного подтверждения.
- [ ] Проверить сообщения о невозможной цели, весах не в сумме 100%, баллах вне диапазона, дробных значениях и нуле в максимальном балле. Сверить хотя бы один расчёт вручную.
- [ ] Проверить экспорт локальной диагностики: только по явному действию пользователя; нет автоматической отправки. Просмотреть содержимое файла и подтвердить, что privacy policy описывает его фактические поля.
- [ ] Проверить, что release AAB не содержит секретов и development URL, а privacy policy и описания относятся к этому же релизу.

## 4. Подготовить карточку магазина

- [ ] Вставить RU/EN тексты из `store-listing.md`: название до 30 символов, short description до 80, full description до 4000. Не вставлять отдельный список keywords в описание. [Поля карточки](https://support.google.com/googleplay/android-developer/answer/9859152?hl=en)
- [ ] Иконка: **512×512**, 32-bit PNG с alpha, до **1024 KB**.
- [ ] Feature graphic: **1024×500**, JPEG или 24-bit PNG без alpha.
- [ ] Минимум два скриншота; JPEG или 24-bit PNG без alpha; каждая сторона 320–3840 px, длинная не больше двух коротких. Практический набор: четыре кадра 1080×1920 для каждой локали.
- [ ] Для кадров использовать реальное UI релизной версии: обзор курсов, детали с работами, расчёт цели и локальные настройки/backup. Не обещать уведомления, синхронизацию или интеграции, которых нет.
- [ ] Проверить отсутствие цен, рейтингов «№1», чужих логотипов и неподтверждённых обещаний в графике. [Требования preview assets](https://support.google.com/googleplay/android-developer/answer/9866151?hl=en)
- [ ] Указать контролируемый владельцем support email, который доступен пользователям.

## 5. Privacy и декларации

Даже приложение без сбора данных должно заполнить **Data safety** для закрытого, открытого теста и production; исключительно internal testing имеет исключение. Локальная обработка, которая не передаёт данные за пределы устройства, не считается сбором по определению этой формы. [Data safety](https://support.google.com/googleplay/android-developer/answer/10787469?hl=en)

- [ ] Разместить privacy policy на действующем публичном URL без ограничений по географии или логина. Policy должна быть веб-страницей, не PDF. Доступ к тексту или ссылке нужен и внутри приложения. Указать приложение/разработчика, контакт, хранение и удаление данных. [User Data policy](https://support.google.com/googleplay/android-developer/answer/10144311?hl=en)
- [ ] Для окончательной сборки без сетевой аналитики, аккаунтов и рекламных SDK: кандидат ответа Data safety — **нет сбора и передачи данных разработчиком**. Перед отправкой отдельно сверить SDK, встроенные WebView и экспорт через Share. Экспорт пользователем в выбранное им приложение должен быть явно описан, а не замаскирован фразой «данные никогда не покидают устройство».
- [ ] Проверить локальное удаление курсов/данных и поведение Android backup. Не обещать, что файл, который пользователь отправил другому приложению, можно удалить из GradeDock.
- [ ] **Ads:** No. **App access:** все функции доступны без логина. **In-app purchases:** отсутствуют. Заполнить content rating, target audience и прочие декларации, которые фактически запросит Console. Содержание приложения нужно описывать по его реальным функциям. [Подготовка к review](https://support.google.com/googleplay/android-developer/answer/9859455?hl=en)
- [ ] Не заявлять официальное сотрудничество с AITU, автоматическое получение университетских данных или гарантированный официальный GPA. Расчёт зависит от весов и правил, введённых пользователем.

## 6. Тестирование и production

- [ ] Сначала загрузить signed AAB в **Internal testing**, проверить pre-launch report и протестировать установку через Play.
- [ ] Для бесплатного доступа добровольцев в **Closed testing платного приложения** подготовить 12–20 отдельных **one-time paid-app promo codes** в Console и объяснить, как их активировать. По правилам Google обычные closed/open testers покупают paid app; internal testers получают её бесплатно. Переход из Internal в Closed требует сначала отказаться от internal test и затем подключиться к closed. [Настройка tracks](https://support.google.com/googleplay/android-developer/answer/9845334?hl=en)
- [ ] Владелец принимает условия promo codes; создать отдельный одноразовый код каждому участнику. Для paid app не нужен in-app SDK; лимит Google — до 500 non-subscription кодов на приложение за квартал. Доступ к платному приложению по промокоду не отменяет отдельный closed-test opt-in. [Создание промокодов](https://support.google.com/googleplay/android-developer/answer/6321495?hl=en)
- [ ] Если личный аккаунт создан после **13 ноября 2023**, запустить **Closed testing**: минимум **12 тестировщиков**, каждый должен оставаться opted-in **14 дней непрерывно**. Затем подать заявку на production access, описать реальные тесты и исправления. Прохождение календарного срока само по себе не гарантирует допуск. [Требования к тестированию](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)
- [ ] Собрать обратную связь: понятен ли смысл пустого результата, удалось ли восстановить backup, насколько ясны оценки и цели. Исправить дефекты до заявки.
- [ ] Включить **Managed publishing**, если хотите самостоятельно выбрать момент публичного выпуска после review. [Управление публикацией](https://support.google.com/googleplay/android-developer/answer/9859654?hl=en)
- [ ] Проверить цену, страны распространения, тексты, возрастные декларации, email и policy URL перед финальным Send for review / Publish. Эти действия выполняет владелец аккаунта.

## 7. После выпуска

- [ ] Еженедельно смотреть продажи, возвраты, установки, отзывы и Android vitals в Console; не добавлять сетевой SDK только ради первых метрик.
- [ ] Отвечать на обращения, фиксировать воспроизводимые баги и выпускать исправления с новым `versionCode`.
- [ ] Через 30 дней сравнить продажи и поддержку с затраченным временем. Продолжать развитие по реальным потребностям пользователей.
- [ ] Перед каждым обновлением проверить текущий target API, зависимости, Data safety и правила Google Play. Крупных ежемесячных инфраструктурных платежей у этого MVP нет.

## Что требуется от владельца перед выпуском

1. Собственный Play account, $25 при новой регистрации, 2FA и проверки личности/устройства.
2. Payments profile и реквизиты банка для международного USD-перевода; подтверждение юридической и налоговой информации по запросу Google.
3. Подтверждение developer/support/privacy контакта и privacy policy; рабочий публичный URL.
4. Проверка на Android-устройстве; 12 реальных тестировщиков для нового личного аккаунта, промокоды для бесплатного доступа к paid closed test.
5. Собственный защищённый upload key для release, если окончательная AAB ещё не подписана им.
6. Юридическое принятие условий и окончательное решение о платной цене, странах и публичном выпуске в Console.

Платежи, юридические соглашения, документы, банковские данные и публикация от имени владельца автономно не выполнялись. Точный статус сборки и проверки указан в README и итоговом отчёте проекта.
